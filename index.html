The problem

Four tools, one thread that keeps breaking

Context is lost at every handoff

The requirement lives in Jira, the test case in Zephyr or Xray, the automation in a repository and the evidence in a shared folder. Each step starts by reconstructing the previous one.

Coverage depends on who picked up the ticket

Every engineer turns a story into tests their own way. Two people, two different scenario sets, and no shared standard for what "covered" means.

Publishing results is the step nobody has time for

Evidence is attached late or not at all, and the dashboards leadership looks at lag behind what the team already knows.

FlowQA keeps the whole thread in the editor, where the code already is: the story comes in from your test-management tool, the journey carries it through, and the results go back out.

Setup

One command, ten questions, a working project

@flowqa_ /setup_project runs a wizard that fits FlowQA to the team instead of the other way round. It can integrate an existing test structure or scaffold a new one.

  1. Existing structure or from scratchPoint it at your current tests and page objects; nothing is overwritten.
  2. Client, project and squadNames that follow the results all the way to the dashboard.
  3. IntegrationJira with Zephyr Scale, Zephyr Essentials, AIO Test or Xray; Azure DevOps with Test Plans.
  4. PlatformWeb, Mobile, API or Desktop.
  5. Framework and languagePlaywright (TypeScript, JavaScript, Python), Cypress (TypeScript, JavaScript), Selenium (Python, Java, C#), Robot Framework.
  6. BDD, data formats and Code modeGherkin on or off, how test data is stored, and whether Code QA runs isolated.
  • Project scaffolded in place (195 files in the run shown here), existing automation preserved
  • Dependencies installed, .gitignore updated
  • MCP servers start automatically with the project; Playwright MCP is optional via /configure_mcp_playwright

Architecture

Built as a platform, delivered as an extension

In the editor

Two chat participants

@flowqa_ runs the full QA flow. @flowqa_code_ is the Code QA mode, with TEA enabled, for work that stays close to the code.

Model

LLM-agnostic by design

FlowQA orchestrates the journey, the prompts and the integrations. The model is whichever one your Copilot runs, so a model change is not a product change.

Tooling

MCP servers, started for you

MCP servers start automatically with the project. Playwright MCP is optional and configured with one command.

Backend

Azure Functions API, multi-tenant

A multi-tenant platform with per-team licensing sits behind the extension; the status bar shows the license state.

Visibility

Metrics dashboard

A Next.js dashboard reads the published results: coverage, execution and trends by client, project and squad.

Pipeline

Quality Gate engine

CI/CD templates turn test results into gates, so a red build means a real regression and nothing else.
